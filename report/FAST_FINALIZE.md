# 提出PDFの高速最終化

MiKTeX/upLaTeXによる全文再組版を避け、監査済み本文ページを保持したまま、問題のあった表紙とPDF 7ページだけを再組版する最終化手順です。

## 実行

リポジトリルートから次を実行します。

```powershell
& .\report\build_fast.ps1
```

処理内容:

1. `report/final_report.pdf`を読み込む。
2. 表紙をA4で再作成する。
3. PDF 7ページの「MATLAB / Simulinkプログラム」を、和文中心の説明と番号付き手順で再作成する。
4. その他のページは再レンダリングせず、そのまま保持する。
5. 差し替えた2ページだけを300 dpiで固定化し、CIDフォントへの表示依存を除去する。
6. 一時PDFを生成してから`report/final_report.pdf`を置換する。
7. ページ数、サイズ、SHA-256を出力する。

## 採用理由

- `uplatex` 2回と`dvipdfmx`を用いる従来経路は1回約60秒を要した。
- 和文と欧文の境界を個別の空白調整で補修する方式は再発しやすかった。
- 最終提出までの時間を優先し、問題のない本文ページには触れず、視覚上の問題が確認された2ページだけを独立したPDF生成系で置換する。
- 表紙とPDF 7ページは最終段階で画像化し、環境による日本語フォント差を避ける。

## 依存関係

- Python 3
- `reportlab`
- `pypdf`
- `pypdfium2`

`build_fast.ps1`は依存パッケージがない場合のみユーザー領域へ導入します。

## 検証済み内容

旧18ページPDFを入力とした独立環境の試験では、次を確認しました。

- A4、18ページを維持
- 変更ページは表紙とPDF 7ページのみ
- その他16ページのrender差分0
- 表紙から「レポートタイトル」と記入用下線を除去
- PDF 7ページの日本語擬似コード崩れを解消
- 200 dpiで全18ページを描画可能
- 差替ページの非埋込みフォント0

この検証は高速最終化処理そのものに対するものであり、リポジトリ上の20ページPDFへ適用した後は、ページ数・SHA-256を改めて記録してください。

## 制約

この手順は本文全体のLaTeX再組版ではありません。数値、図、式、表、参考文献および既存の検証済みページを変更せず、提出直前の表紙・組版問題を短時間で解消するための限定的な最終化です。
